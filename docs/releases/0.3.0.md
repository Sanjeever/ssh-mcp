# 0.3.0

本版完善 Agent 调用诊断、命令输入输出和文件发布，增加本机 SSH Agent 与单跳跳板机。继续通过一个 npm 包分发单文件入口，要求 Node.js 22+。当前参数与操作边界见[使用指南](../usage.md)，维护入口见[开发与发布](../development.md)。

## 变化

- `ssh_exec` 支持最多 1 MiB UTF-8 标准输入，发送完成后关闭输入端；省略输入也发送 EOF。支持输出头部、尾部或两端保留，返回各流接收与省略字节数、截断状态及退出信号。
- stdout 与 stderr 分别保存最多 96 KiB 和 32 KiB，默认 `output_mode=head_tail`，超限继续排空。固定大小缓冲区避免输出块数量随运行时间增长。
- 参数校验失败提供结构化 `ssh_input_invalid` 与字段问题详情；操作失败增加阶段、可识别原因和状态，连接错误标明所在跳的服务器 ID。保留已有操作错误码，不自动重试命令。
- 四个工具增加 MCP annotations。传输在客户端提供 progress token 时发送经过节流、严格递增的字节进度，结束后停止通知。
- `ssh_upload` 增加显式 `atomic=true`，先写同目录临时文件再发布。覆盖使用 OpenSSH POSIX rename 扩展，禁止覆盖使用 hardlink 扩展，不支持时失败。结果区分尚未发布、结果未知、已发布及临时文件可能残留。
- 原子上传新文件采用 0600，覆盖保留普通 POSIX 权限位与 uid/gid；无法设置时在发布前失败。不保留 ACL、扩展属性和已有硬链接关系，不承诺断电持久性。
- SFTP 使用最多 4 个块的有限并发窗口，处理短读和乱序响应，持续检查 128 MiB 上限及源增长。失败保留已确认写入字节数，不提供断点续传承诺。
- 增加 `AGENT_SOCKET`，支持 Unix socket 与 Windows OpenSSH named pipe。Agent 连接随调用取消和超时清理，不开启 Agent forwarding，不引入 Pageant/Cygwin 辅助程序。
- 增加 `JUMP_SERVER_ID`，引用另一台已配置服务器。跳板和目标分别认证、验钥，目标跳的 15 秒上限包含转发与目标握手，整条链共同受总超时和取消约束。启动时拒绝未知、自引用和嵌套跳转。
- CI 增加隔离 OpenSSH 服务端测试；安装包验收增加标准输入及 Agent 与跳板机组合调用。保持正常安装、禁用脚本、忽略可选依赖三条安装路径。

## 升级说明

已有四个工具及必填参数保留。长输出由原先按到达顺序保存合计 128 KiB，改为两个流分别保留配额，默认保存两端；需要头部时显式设置 `output_mode=head`。短输出保持原样。

参数校验失败现在包含结构化结果，不含执行或传输结果字段；客户端应按输出 Schema 识别失败形态。`auth_type` 增加 `agent`，列表增加可选 `jump_server_id`。原子上传默认关闭，原有直接上传方式继续可用。

配置变更后重启 MCP 进程。主机证书限制、首次连接信任策略和超时后远端状态可能不确定等边界继续适用。

## 本地发布准备验证

2026-10-17 在 macOS 26.6.2 arm64、Node.js 26.11.0、pnpm 11.20.0 下验证类型检查、单文件构建和完整测试。测试启用临时 OpenSSH 与系统临时 ssh-agent，覆盖独立服务端互通、原子发布、两台 sshd 之间的跳转及错误注入。

实际 tarball 通过正常安装、禁用脚本与忽略可选依赖三种隔离安装，核对版本、唯一应用包、CLI、四工具、标准输入、Agent 与跳板机。最低 Node 22.0.0、六平台原生与公开发布状态分别以本版 [CI](https://github.com/Sanjeever/ssh-mcp/actions/workflows/ci.yml) 和[发布工作流](https://github.com/Sanjeever/ssh-mcp/actions/workflows/release.yml) 的实际记录为准。

## 传输测量

同日在上述本机环境运行 `scripts/benchmark-transfer.ts`。环回 SFTP 服务为每次读写请求注入固定延迟，每个组合取单次样本，对比窗口 1 与 4；这不是公网带宽测试，也未测量高延迟下的 120 MiB 完整矩阵。

| 文件与请求延迟 | 方向 | 窗口 1 | 窗口 4 |
| --- | --- | ---: | ---: |
| 4 MiB，50 ms | 上传 | 9,889 ms | 2,494 ms |
| 4 MiB，50 ms | 下载 | 9,917 ms | 2,561 ms |
| 4 MiB，100 ms | 上传 | 19,475 ms | 4,889 ms |
| 4 MiB，100 ms | 下载 | 19,608 ms | 5,005 ms |
| 120 MiB，0 ms | 上传 | 406 ms | 277 ms |
| 120 MiB，0 ms | 下载 | 470 ms | 329 ms |

1 KiB 文件主要受单请求和关闭流程影响，窗口增大收益很小。采样内存包含同进程测试服务端；4 MiB、100 ms 组合的峰值 RSS 为 48–56 MiB，整个串行测量过程为 41–108 MiB，受 GC 与先前样本影响，不能视为独立客户端的内存上限。复现方法与完整矩阵入口见[传输测量说明](../development.md#文件传输性能测量)。

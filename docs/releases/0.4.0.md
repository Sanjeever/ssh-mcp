# 0.4.0

本版完善 Agent 的输出读取、连接诊断、文本编辑和长任务观察，并限制远端操作并发。继续通过一个 npm 包分发单文件入口，要求 Node.js 22+。当前参数与操作边界见[使用指南](../usage.md)，维护入口见[开发与发布](../development.md)。

## 变化

- `ssh_exec` 可分别降低 stdout 与 stderr 返回预算，保留原有默认上限、头尾模式、持续排空和失败输出。显式 `save_output=true` 返回 `output_id`，通过 `ssh_output` 分页读取同一次执行的输出，无需重跑命令。
- 输出保存使用当前 MCP 会话的有界内存，每流前 4 MiB，会话最多 8 份，完成后 10 分钟过期。结果区分实际接收量与可读取量；分页保留完整 UTF-8 字符，运行中的不完整字符等待后续读取。`ssh_output_forget` 可释放已结束操作的输出及关联任务结果，归还容量。
- `ssh_probe` 显式验证主机信任、认证与 SFTP 能力，返回已验证主机指纹及原子发布扩展支持。探测不执行 Shell、不写远端文件，沿用 known_hosts 策略。SFTP 缺失与 SSH 连接失败分别表达，网络错误细分 DNS、拒绝连接、不可达、连接超时与重置。
- `ssh_read_file` 按行读取有界 UTF-8 普通文本文件，保留 CRLF 与末尾换行，返回内容版本。`ssh_edit_file` 要求版本前提及唯一精确匹配，复用原子上传发布，保留普通权限位和 uid/gid。发布前复查内容，发现变化时拒绝；不宣称 SFTP 具有原子比较交换能力。
- `ssh_exec_start` 接受会话内异步命令，`ssh_task_status` 查询状态及最终结果，`ssh_task_cancel` 请求取消。运行中可读取增量输出；任务归属当前 stdio 会话，不使用持续 Shell，不跨进程恢复，不要求客户端支持协议层 Tasks 扩展。取消和断连仍不能证明远端进程停止。
- 同步与异步远端操作共用全局、每服务器并发限制和有界等待队列，单跳同时计入跳板与目标配额。排队计入总超时，取消排队项不建立连接，满队列明确拒绝，不自动重试。
- CI 增加独立 Dropbear / BusyBox 隔离容器测试，分别覆盖有、无 SFTP 子系统。安装包验收实际调用全部工具，覆盖输出、探测、文本、异步任务和容量释放；独立 OpenSSH 测试覆盖文本原子编辑成功路径。

## 升级说明

原有四个工具及默认输入输出行为保留，新增工具通过 MCP 工具发现取得；升级后重启客户端的 MCP 进程。配置仍在启动时固定。

远端操作默认最多全局 4 个、每服务器 2 个，等待队列 32 个。需要调整时设置 `SSH_MCP_MAX_CONCURRENT`、`SSH_MCP_MAX_CONCURRENT_PER_SERVER` 和 `SSH_MCP_MAX_QUEUE`。排队也消耗调用总超时，队列满可能返回新的 `ssh_queue_full`。

异步命令始终保存输出，与同步显式保存共用容量。读完后可主动释放；活动操作须先取消或等待结束。任务状态查询成功不表示远端命令成功，应检查 `status` 和最终 `result.error`。

文本工具最大文件为 1 MiB，不支持符号链接或二进制；编辑要求服务器支持 POSIX rename 扩展。`expected_revision` 用于发现内容变化，严格并发写入仍需与外部写入者协调锁。ACL、扩展属性和断电持久性边界沿用原子上传。

## 验证范围

2026-10-17 在 macOS arm64、Node.js 26.11.0、pnpm 11.20.0 下通过类型检查、单文件构建及完整 60 项测试。测试显式启用临时 OpenSSH 和隔离 Dropbear / BusyBox 容器，无跳过项；未连接真实服务器或修改用户 known_hosts。

最低 Node.js 22.0.0 下完整常规测试 57 项通过，3 项独立服务端测试按设计跳过。0.4.0 实际 tarball 在 Node.js 26.11.0 与 22.0.0 下分别通过正常安装、禁用脚本和省略可选依赖三种隔离安装，核对单包分发、CLI、全部工具、标准输入、Agent 与跳板机。锁文件经离线更新核对，依赖未变化，未产生锁文件内容差异。

本机验证与最低 Node 版本、六平台原生运行及公开发布分别记录。完整远端流水线与公开发布结果以 [CI](https://github.com/Sanjeever/ssh-mcp/actions/workflows/ci.yml) 和[标签发布工作流](https://github.com/Sanjeever/ssh-mcp/actions/workflows/release.yml) 为准。

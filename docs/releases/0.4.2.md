# 0.4.2

本版增加共享环境文件配置，减少多个 Agent 客户端之间重复维护服务器信息。继续以单个 npm 包分发，要求 Node.js 22+。

## 变化

- 新增 `--env-file <路径>` 和 `--env-file=<路径>`，每次启动读取一份指定的 `.env` 文件，沿用现有 `SSH_MCP_*` 变量名及配置校验，不增加运行依赖。
- 同名进程环境变量优先于文件值，包括显式空值；不同变量合并后校验认证方式、服务器字段、跳板引用和并发限制。不传参数时沿用原有环境变量配置。
- 文件读取失败阻止启动，不回退到其他配置。应用错误不输出文件内容，stdout 继续专用于 MCP 协议。

## 升级说明

将客户端中的 `SSH_MCP_*` 配置集中到本机文件，例如 `~/.config/ssh-mcp/servers.env`；各客户端在包名后追加 `--env-file` 和同一文件的绝对路径，并移除已迁移的环境变量，避免旧值覆盖文件。文件格式及 Codex、Claude Code 示例见[共享环境文件](../usage.md#共享环境文件)。

配置仍在启动时固定，修改文件后须分别重启各客户端中的 SSH MCP 进程。文件内的相对配置路径仍基于进程工作目录，未改为相对于环境文件目录。

Node 部分版本会提前读取脚本参数中的 `--env-file`，最低支持版本 Node 22.0.0 和本机 Node 26.11.0 均复现此行为。环境文件须使用绝对路径，并专用于 `SSH_MCP_*` 配置，不放入 `NODE_OPTIONS` 等运行时设置；读取失败可能由 Node 在应用启动前报告。保留单文件入口，不增加启动包装层。

0.4.2 实际 tarball 已通过完整性校验，以及正常安装、禁用脚本和省略可选依赖三种隔离安装。每条安装路径均验证环境文件启动、命令执行和标准输入，并沿用全部工具、Agent、跳板机和 SFTP 验收。锁文件经离线更新核对，依赖未变化，未产生内容差异。

本机还使用 Node.js 22.0.0 通过配置与真实 stdio 的 11 项测试。完整最低版本验证、六平台原生运行与公开发布以[标签发布工作流](https://github.com/Sanjeever/ssh-mcp/actions/workflows/release.yml)为准，不将本机结果视为其他平台的运行证据。

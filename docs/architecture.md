# 架构与设计约束

本文记录有意保留的设计决策、原因与边界，作为后续实现变更的约束。当前模块细节以代码为准，用户参数、默认值与操作方式见[使用指南](usage.md)。约束需要调整时，应结合原有原因和用户契约明确作出决策并更新本文。

## 边界与职责

项目是由 MCP 客户端启动的 stdio 进程，远端操作限于配置中的 SSH 服务器。配置在启动时加载并固定；启动与服务器列表不探测网络，避免客户端初始化依赖每台远端主机是否可达。调用必须精确选择服务器，避免猜测目标导致误操作。

主要边界为配置加载、MCP 协议与校验、SSH 连接与信任、命令执行及 SFTP 传输。配置层负责本机配置合法性，协议层负责工具契约，SSH/SFTP 层负责远端操作与资源释放。源码位于 `src/`，可执行契约见 `test/`。

能力探测由调用方显式选择，使用正常验钥与认证流程，不执行 Shell 或通过写文件探测扩展。SFTP 扩展从固定版本 ssh2 已解析的协商结果读取；当前库缺少公开查询 API，这一局部依赖须随库升级重新验证，不能用伪造文件操作代替查询。

当前产品范围不包含 HTTP/SSE、Web UI、数据库、动态服务器配置工具或后台守护进程。扩展这些能力属于产品和架构变化，需要相应需求支持。

## 协议、凭据与生命周期

stdout 是 MCP 协议通道，诊断写 stderr，不能混入启动 banner。工具字段采用 snake_case，Schema 拒绝未知参数，避免拼写错误被静默接受。默认日志不记录凭据、完整命令、输出或整份参数，工具列表不暴露凭据和私钥路径。

使用密码、已有私钥或显式本机 Agent 端点认证，不修改远端 `authorized_keys`。Agent 协议复用 SSH 库，socket 归本次调用管理，不开启 Agent forwarding。支持 Unix socket 与 Windows OpenSSH named pipe，不引入 Pageant/Cygwin 外部辅助程序。本机文件访问继承 MCP 进程账号权限，不提供额外工作区沙箱或同账号进程间的凭据隔离。

每次远端调用使用独立连接或显式配置的单跳连接链，完成后关闭；不使用连接池、持续 Shell 或 PTY，使会话状态和资源归属限定在一次调用内。跳板与目标分别在认证前验证主机密钥，目标地址由跳板连接，不依赖本机 SSH 配置或代理命令。未知、自引用或嵌套跳转在启动时拒绝。命令交给远端默认 Shell，不经本机 Shell，不自动输入 sudo 密码，不承诺交互式多因素认证。

取消、总超时、会话关闭、stdin EOF 与终止信号都应清理活动连接链及 Agent socket。总超时与每跳独立握手上限须分别分类，目标跳包含通道建立和目标握手，不能因定时器触发顺序误报。关闭连接不能证明远端操作已停止，因此不自动重试命令，失败保留已有输出或传输进度，缺失退出状态不能伪造成功。

命令输出设合计保存配额，超限继续排空，避免无限内存增长或因停止消费而阻塞远端。配额和文本处理行为以实现与回归测试为准。

返回预算与显式保存输出分别限制。显式保存使用当前 MCP 会话的有界内存，完成后过期，不默认持久化命令内容，不跨会话读取。保存耗尽时仍排空远端输出，结果须区分实际接收量与可读取量，不能把保存 EOF 当成完整输出承诺。

## 主机信任

信任校验必须发生在认证之前。未知主机、已知主机密钥变化、撤销与信任文件无效是不同状态，不能把校验失败统一当作首次连接。首次接受须成功持久化后才继续认证，写入失败不能降级为内存信任；strict 不创建信任。已有记录不自动替换。

复用用户 OpenSSH known_hosts 时，须保留内容、注释、已有权限、符号链接入口及缺少末尾换行的文件。检查与追加要避免同一进程中的重复或冲突信任，写入前重新验证；不承诺协调外部写入者。主机匹配、全文件撤销规则与权限的用户可见语义见[使用指南](usage.md#主机信任)。

密钥格式交给 SSH 库解析，项目承担 known_hosts 记录与匹配规则，不另写 SSH 字节协议解析器。迁移采用 ssh2 时，已确认其不支持 OpenSSH 主机证书协商，因此匹配 CA 规则明确拒绝且不追加信任。不得用忽略 CA、关闭验证或调用本机 ssh 绕过限制。若更换后端或新增证书支持，应重新评估此决策并验证信任语义。

## 文件传输

使用 SFTP 传输单个普通文件，不回退 SCP、不递归、不创建父目录。远端路径由远端 SFTP 解释，不能用本机路径规则改写。预检之外须持续限制实际字节数，防止源文件增长绕过上限；读写需施加背压，处理本地与远端关闭错误。

默认禁止覆盖必须由创建或发布动作保证排他性，不能依赖“先检查、后普通写入”。下载先写同目录临时文件，完整传输并成功关闭后再发布，以保留原目标；禁止覆盖使用排他硬链接，显式覆盖使用系统重命名。硬链接不可用时明确失败，不能改用可能覆盖目标的退路。变更此方案时须维持并发冲突保护与失败清理，并验证各平台文件系统行为。

上传默认直接写远端目标，失败可能遗留部分文件。显式原子上传先在同目录排他创建临时文件，关闭完成后发布。覆盖使用 OpenSSH POSIX rename 扩展，禁止覆盖使用 hardlink 扩展，缺少所需扩展明确失败。原子可见性不等于断电持久性，也不承诺保留 ACL、扩展属性和硬链接关系。

覆盖时保留普通 POSIX 权限位与 uid/gid，设置失败须在发布前停止，新文件采用 0600。发布请求发出后丢失结果，状态须保持不确定；收到成功后清理失败仍须表达目标已发布。清理服从总超时与连接生命周期，不为清理自动重连；可能残留的临时路径随结果返回。

## 单包分发与发布

应用、测试与工程脚本统一使用 strict TypeScript 和 NodeNext ESM，类型检查覆盖全部维护源码。测试与工程脚本通过开发依赖 tsx 执行，用户安装包仍运行构建后的 JavaScript。应用使用官方 MCP TypeScript SDK、ssh2 和 Zod，不依赖 Go 或本机 ssh/scp。采用 esbuild 将应用与运行依赖内嵌为单个 JavaScript 入口，以单个 npm 包分发，减少用户安装时的依赖下载与环境差异。选择背景及测量条件见 [0.2.0](releases/0.2.0.md) 与 [0.2.1](releases/0.2.1.md) 记录。

ssh2 使用 JavaScript 加密实现与内嵌 WASM，不加载可选原生加速模块，保证用户无需编译工具或安装脚本。构建必须拒绝非 Node 内置的外部导入，并保留实际内嵌依赖的许可。依赖版本在开发依赖与锁文件固定；安装和首次启动不下载应用二进制、不运行构建工具、不要求开发依赖。

根 `package.json` 的 `version` 是唯一应用版本源，CLI 与 MCP server info 读取同一字段，避免多个入口分别维护版本。正式版本须有非空中文日志。

发布集中构建一次，同一 tarball 用于原生安装验证和公开发布，避免验证对象与发布对象不同。npm 采用 OIDC，不引入日常 `NPM_TOKEN`；发布失败停止，恢复时核对原产物完整性。具体命令、账户核对项与恢复步骤见[开发与发布](development.md#版本与发布)。停止平台子包和独立二进制分发后，历史版本与旧包保留，不自动删除、unpublish 或 deprecate。
